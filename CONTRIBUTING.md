# Contributing

Thank you for taking the time to improve this project. Contributions should be focused, reproducible, and easy to review.

## Before opening a pull request

Please search existing issues, explain the problem you are solving, and keep the change limited to that problem. For code changes, include the commands you ran and the result. Documentation changes should describe the behavior that is true today rather than promise future functionality.

## Pull requests

Use a clear title, describe the motivation and implementation, and call out any known limitations. Do not commit credentials, generated build output, local configuration, or unrelated formatting changes. A maintainer may ask for a smaller or more focused patch.
